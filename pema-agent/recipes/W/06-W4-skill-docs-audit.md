# W4 — `pema-web-design` skill, docs and full audit

## Goal
Turn W0–W3 into a repeatable workflow that another session can follow, like the app skills, and prove that the whole
package is consistent before the push.

## Read first
1. `PLAN-AI01-W.md` §5 (gate), §6 (acceptance), decision D6.
2. `.claude/skills/pema-web-to-canvas/SKILL.md`, `web-changes.md` and `scripts/pending.cjs`: the change-log pattern
   to mirror.
3. `.claude/skills/pema-canvas-to-kmp-compose/SKILL.md`: the spec-first build pattern to mirror for Next.js.
4. `CLAUDE.md`, `design-specs/README.md`, `pema-agent/frontend/visual-ref/old/README.md`, and the W0–W3 reports.

## Ingredients
- `.claude/skills/pema-web-design/SKILL.md`, final. Frontmatter `name` and `description`; the description says when
  to use the skill: "web screens missing from the web canvas", "build/port a Next.js screen from the web canvas",
  "refresh old-web screenshots/specs". Sections:
  1. Setup: old web on 4173, finance on 4174, design-viewer on 4180, `PLAYWRIGHT_MODULE`.
  2. Where things are: the plan §3 tree.
  3. Refresh: inventory → shots → snapshot → specs, with `--check` at each stage.
  3b. The owner rule: complete coverage of the old web's UI, drawn in the app's design language. Differences
      between old web and app go to `notes.json`, never into removed UI.
  4. Add or change a web screen in the canvas: blocks, notes, check, open the PNGs.
  5. Build a Next.js screen from a spec: read `get_web_screen(<ID>)`, use the `src/ui` components named in Layout, and
     record a note afterwards with `record_web_note`.
  6. Push to claude.ai/design: the same safe steps as pema-web-to-canvas §6, with the web project id from W5.
  7. Finish: coverage, change log, SECTION_PROGRESS, commit, report.
- `.claude/skills/pema-web-design/references/coverage-web.md`, generated by a script from `inventory.json` and the
  canvas so it cannot drift. One row per id: old web reach, web canvas frame, app canvas codes, Next.js route and
  status.
- If D6 is approved:
  - `.claude/skills/pema-web-design/web-design-changes.md`: a log with a "Sync baseline" line, "Pending" and "Done"
    sections, and an entry template.
  - `scripts/pending-web.cjs`: lists visible changes in `pema-agent/frontend/src/app/**` and `src/ui/**` since the
    baseline that have no log entry.
- `CLAUDE.md`: a new section "Web design canvas", 4–6 lines.
  - Pointer to the skill, the canvas, `design-specs/web/` and the MCP web tools.
  - If D6: the rule "visible change in `pema-agent/frontend` → entry in `web-design-changes.md` in the same commit;
    `pending-web.cjs` must show no ✗ before committing".
  - Keep the existing sections word for word.
- `design-specs/README.md`: one paragraph and a table row for `web/`. The app part stays unchanged.
- `SECTION_PROGRESS.md`: a checkpoint (what was added, the viewports, how it was checked).

## Steps
1. Write the skill, the coverage generator and the docs.
2. Full audit from a clean shell, in this order, saving each output:
   1. `web-inventory.cjs --check`;
   2. `web-shots.cjs --check`;
   3. `web-specs.cjs --check`;
   4. `web-canvas.cjs check … WA,…,WH` at 1440, 1920 and 390;
   5. app `design-specs.cjs --check`;
   6. `pending.cjs`;
   7. `pending-web.cjs` (if D6);
   8. the MCP stdio smoke: `get_web_screen` for one id per group, and `get_screen("A1")` unchanged.
3. Cross-check the counts:

   | Item | Expected |
   |---|---|
   | inventory ids | N |
   | screenshots | N × 5 (+ legacy copies) |
   | specs | N |
   | canvas screens | N |
   | coverage rows | N |
   | snapshot items missing from specs or frames | 0 |

   Report any mismatch as a defect. Do not hide it.
4. Follow the skill once yourself on one screen, as a "new session": refresh one id end to end with only the
   SKILL.md. Fix every step where you needed knowledge that is not written down.

## Acceptance
- All audit commands exit 0. The counts table is all equal.
- `CLAUDE.md` diff only adds the new section.
- A fresh reader can run the refresh with only `SKILL.md` (step 4 passed, and the gaps found are fixed).
