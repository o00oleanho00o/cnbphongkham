# W2 — Generated screen specs for the old web, served by the MCP server (way 2)

## Goal
Produce one spec per inventory id, `design-specs/web/screens/<ID>.md`, generated like the app specs. A builder (Next.js
now, KMP later) can then build or check a web screen from the spec alone, without re-reading `prototype/`. Serve the
specs through the existing `pema-design` MCP server with new, additive tools.

**Owner rule (plan §0, principle 0): the result must contain EVERY piece of UI the old web has.** Nothing is filtered. The app design gives the look (tokens, blocks, kit); the old web gives all content. A web spec lists every field, action, status, filter and text of the old
screen (from the snapshot), expressed with the app's blocks and kit components. The app spec(s) in `app_canvas` are
read to reuse their block choices and wording, and to record differences.

   `badge`, `dialog`, `field`, `empty-state`, table and tabs components). This is the target vocabulary.

## Ingredients
- `.claude/skills/pema-web-design/scripts/web-snapshot.cjs`: for every id at 1440×900 (and at 390×844 for pages),
  reach the screen with `old-web.cjs` and extract a **structured** snapshot into `design-specs/web/snapshot.json`.
  Text only, no pixels. Per id:
  - `regions`: shell, header, content columns with their bounding boxes, and the CSS grid or flex template of the
    content.
  - `headings` (level, text).
  - `actions`: buttons and links (label, primary/secondary/danger from class, disabled).
  - `fields`: label, type, required, options for selects and radios, placeholder.
  - `tables`: column headers, row count, the first row as text.
  - `chips_tabs`: label, selected.
  - `badges_status`: text and colour class.
  - `kpis`: label, value, hint.
  - `notices`: text of info, warning and business-rule boxes, verbatim.
  - `empty_states`.
  - `tokens_used`: computed colours, radius and font sizes mapped to the nearest `tokens.json` name. A colour with no
    token within ΔE 3 is listed as `unmatched`.
  - `responsive`: what changes at 390 (columns → cards, hidden sidebar, sheet).
- `.claude/skills/pema-web-design/scripts/web-specs-lib.cjs` and `web-specs.cjs`.
  - `node web-specs.cjs` regenerates `design-specs/web/INDEX.md`, `index.json` and `screens/*.md`.
  - `--check` fails when any of those is stale.
  - `--show=WB1` prints one spec.
  - W3 adds `BLOCKS.md`.
- `design-specs/web/notes.json`, hand-written: keys `screens.<ID>.logic | rules | differences | gotchas | todo`. Seed
  it with what you learn: the source function per screen (e.g. `crm-ui.js › dashboard()`), business-rule sentences,
  and old-web quirks.
- Spec layout. The generated header names the generator, the snapshot hash and "edit notes.json, not this file".
  Sections:
  1. `# <ID> · <name>`: group, kind, and Next.js status (`next_status`).
  2. `## Logic source`: source files and functions, staff-context permission (`pages`, `capabilities`).
  3. `## Next.js target`: route, U step, FEATURE-INVENTORY test id, and the existing page file if built.
  4. `## App canvas`: `app_canvas` codes with links to `../../screens/<code>.md`, and which of their blocks this
     screen reuses. Empty list = no app counterpart.
  5. `## Frame`: viewport, then the shell region sizes.
  6. `## Layout (top to bottom, region → src/ui component)`: the old web's arrangement and content, every region
     as a kit component call with its real text,
     e.g. `<Card title="Lịch trong kỳ"> <Kpi value… /> </Card>`. In W3 this switches to canvas blocks when a frame
     exists; the canvas wins and the snapshot is the fallback.
  7. `## Responsive`: behaviour at 1920, 1280, 1024 and 390, from the snapshot and the W1 overflow data.
  8. `## Tokens`: tokens used, plus `unmatched` colours.
  9. `## Required text (keep verbatim)`, `## Business rules`: from the old web's notices first, then notes.json.
     `## Differences from the app design`: where the app says or does it differently (labels, steps, rules), from
     notes.json; the owner decides later. `## Gotchas`: from notes.json.
  10. `## Images`: links to `pema-agent/frontend/visual-ref/old/<ID>-*.png` (generated by W1, may be absent on a fresh
      clone).
  11. `## Prompt`: a ready prompt such as "Build/port web screen <ID> in pema-agent/frontend using src/ui …".
- MCP, additive only, in `.claude/skills/pema-canvas-to-kmp-compose/mcp/pema-design-mcp.cjs`:
  - `list_web_screens`;
  - `get_web_screen(id)`;
  - `get_web_screen_image(id, viewport="1440x900")`: returns the PNG from `visual-ref/old`, or a clear "run
    web-shots.cjs" message;
  - `record_web_note(id, key, text)`: writes `design-specs/web/notes.json`, then regenerates.
  Also add a resource `pema-design://web-index` and a prompt `port_web_screen`. Existing tools, resources and prompts
  keep their exact names, schemas and output.

## Steps
1. Write `web-snapshot.cjs` and run it. Read 5 snapshots by hand against the screenshots (or against the live page if
   W1 is not merged yet): one page, one tab, one modal, one dialog, one finance tab. Fix the extraction until headings,
   fields and actions match what a user sees.
2. Write `web-specs-lib.cjs` and `web-specs.cjs`, and seed `notes.json` for at least every page and tab. Generate all
   specs.
3. Extend the MCP server and test it over stdio: send `initialize`, `tools/list`, `tools/call get_web_screen
   {"id":"WB1"}` and `tools/call get_screen {"id":"A1"}`. Diff the A1 output against the output before your change:
   it must be identical.
4. Run `web-specs.cjs --check` and the app `design-specs.cjs --check`.

## Acceptance
- Spec count = inventory id count. No spec has an empty Layout section or a `TODO` header.
- Coverage check: every field, action, status, filter and notice of the snapshot appears in the spec's Layout.
  `web-specs.cjs --check` prints the missing items per id and fails when any is missing.
- `node .claude/skills/pema-web-design/scripts/web-specs.cjs --check` exits 0.
- `node .claude/skills/pema-canvas-to-kmp-compose/scripts/design-specs.cjs --check` exits 0.
- The MCP stdio transcript shows the 4 new tools working, and `get_screen("A1")` byte-identical to before.
- `snapshot.json` contains no real personal data; the old web is synthetic. The report states the size of
  `snapshot.json`.
