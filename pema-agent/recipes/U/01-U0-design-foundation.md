# U0 — Design foundation: tokens, UI kit, AppShell, visual harness

## Goal
Give the Next.js FE the old Pema web's look as a reusable foundation: one token source (CSS + JSON for KMP), a small
component kit, an AppShell with the old sidebar, and a Playwright harness that screenshots every route at 5 viewports.

## Read first
1. `PLAN-AI01-U.md` §2, §4.
2. `.agents/skills/design-system/references/` (primitive/semantic/component tokens, `tailwind-integration.md`,
   `component-specs.md`, `states-and-variants.md`), `.agents/skills/brand/SKILL.md`, `docs/23_PEMA_DESIGN_SKILL.md`.
3. `prototype/shared/design.css`, `styles.css`, `workspace-layout.css`; `prototype/clinic-web/index.html` sidebar
   (`data-nav` order: dashboard, today, schedule, patients, followups, studio, resources, services, cashier, ask, guide).
4. Current `frontend/src/app/globals.css` (brand scale, canvas/surface/ink/line/tile already defined) and
   `src/components/{admin,care,ops}`.

## Ingredients
- `src/ui/tokens.css` (Tailwind v4 `@theme`), `src/ui/tokens.json` (same values, generated by a script, for KMP).
- `src/ui/` kit: `AppShell`, `Sidebar`, `TopBar`, `Workspace` (two-column ≥1280, four-column ≥1600 for doctors/services
  as `prototype/README` describes), `Card`, `Tile`, `TableShell` (reuse/extend existing), `Tabs`, `Badge`, `Field`,
  `Dialog`, `Sheet` (mobile), `EmptyState`.
- `scripts/visual-check.ts`: Playwright, enumerates `src/app/**/page.tsx`, logs in against `frontend/mock`, screenshots
  to `visual-ref/new/<viewport>-<route>.png`, fails on `document.scrollWidth > viewport`.
- `visual-ref/old/`: reference screenshots produced by running `prototype/review-desktop.cjs` with
  `PEMA_EVIDENCE_DIR=pema-agent/frontend/visual-ref/old` against the old web on :4173 (read-only use of the script).

## Steps
1. Extract tokens: colours, type scale, spacing, radius, shadows, z-index from the references above; keep the names
   already used in `globals.css` (`brand-*`, `canvas`, `surface`, `ink`, `ink-soft`, `line`, `tile`) and add the
   missing semantic ones. Write `tokens.css` and generate `tokens.json` (`scripts/export-tokens.ts`).
2. Build the kit on the tokens; no hard-coded colours. Each component has a vitest render test and a story-like
   example page under `/dev/kit` (dev-only, excluded from the inventory).
3. `AppShell`: sidebar with the **old order and labels first**, then new groups "Zalo & CSKH" (Inbox, Hàng đợi duyệt,
   Mẫu tin), "Care agent" (Yêu cầu chuyển giao, …), "Quản trị agent" (existing admin routes). Every existing route
   must be reachable; route paths do not change.
4. Capture `visual-ref/old/` once and commit only a `README.md` there (images are git-ignored).
5. Harness: 5 viewports, all routes, overflow assertion, JSON summary; wire `pnpm visual` script.

## Acceptance
- `pnpm lint`, `tsc`, `build`, `vitest` pass; kit components have tests.
- `pnpm visual` runs against the mock BE and reports 0 overflow failures for existing routes rendered inside the
  new shell (pages themselves are restyled in U1).
- `tokens.json` validates against a JSON schema and matches `tokens.css` (test).
- Side-by-side check of `/today` old vs new at 1920×1020: same structure (sidebar width, header, two columns).

## Out of scope
- Do not restyle individual pages (U1). Do not add features. Do not touch `prototype/`.

Use `_REPORT-TEMPLATE.md`; list token names added and any reference conflicts (e.g. design.css vs skill refs).
