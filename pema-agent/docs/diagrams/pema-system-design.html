PHẦN 2

Kiến trúc hệ thống

Hai ứng dụng độc lập chạy cạnh nhau trên một máy chủ: api là CRM, agent là người trả lời khách. Nhân viên chỉ vào qua Next.js; khách chỉ gặp agent qua Zalo.

ĐĂNG NHẬP

Hai phiên, không dùng chung

  • api giữ phiên cookie của nhân viên
  • token gửi agent có aud = pema-agent; api không nhận token đó làm phiên
  • agent kiểm token bằng khóa công khai (JWKS)

BÍ MẬT

Khóa nằm trong DB, mã hóa

  • khóa API của model: api_key_enc
  • bí mật của plugin: secrets_enc
  • khóa mã hóa nằm ở biến môi trường của agent, không ở trong DB

PHẦN 3

Thiết kế harness của agent

Harness là phần bao quanh model: vòng lặp gọi tool, hook, nén ngữ cảnh, trace, cùng cách lắp tool và prompt. Lõi agentcore không biết kênh nào; mọi thứ đặc thù (Zalo, kho tri thức, kỹ năng) là plugin gắn vào lõi.

NGUYÊN TẮC 1

Đầu tư vào tool, không vào vòng lặp

  • vòng lặp nhỏ và ổn định
  • tool lõi dùng chung, không gắn plugin
  • bật tắt từng tool cho từng agent

NGUYÊN TẮC 2

An toàn nằm trong code

  • prompt chỉ nhắc thêm
  • giới hạn là hàm thuần có test
  • nội dung ngoài là dữ liệu, không phải lệnh

NGUYÊN TẮC 3

Cấu hình là dữ liệu

  • vai trò, quy tắc, tool, biến nằm trong DB
  • sửa trên giao diện, áp dụng lượt sau
  • TOML chỉ giữ phần hạ tầng
